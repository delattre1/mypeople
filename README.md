# MyPlow

Self-hosted Claude Code, Codex and Grok teams: a priorities board, live HUD, browser terminal,
Terminal Graph, persistent Boss, engineers, and board backups. This repository contains the
implemented runtime; installing it does not hydrate or generate code from the SEED.

Each machine authenticates its selected agent backend independently. MyPlow never copies,
mounts, or reuses another node's credential store.

## Docker (recommended)

Requirements: Docker Desktop/Engine with Compose. Choose one backend and authenticate it in this
container's persistent home volume.

Claude Code:

```bash
docker compose pull
docker compose run --rm --entrypoint claude mypeople auth login
MYPEOPLE_BACKEND=claude docker compose up -d
```

Codex, using device login for the headless container:

```bash
docker compose pull
docker compose run --rm --entrypoint codex mypeople login --device-auth
MYPEOPLE_BACKEND=codex docker compose up -d
```

Grok is also supported. It is not auto-installed (it ships its own updater and publishes no
install script to pin), so install the CLI yourself, then:

```bash
grok login
MYPEOPLE_BACKEND=grok docker compose up -d
```

Open <http://localhost:9933>. The HUD is at <http://localhost:9933/dashboard>, the Terminal Graph
at <http://localhost:9933/terminal-graph>, and terminal links open port 7681. State and this
node's selected backend login persist in named volumes.

If those ports are already occupied, choose host ports before starting. Links generated by the
board and HUD will use the selected terminal port:

```bash
MYPEOPLE_BACKEND=codex \
MYPEOPLE_TODO_PORT=39933 MYPEOPLE_HUD_PORT=39900 MYPEOPLE_TTYD_PORT=37681 \
docker compose up -d
```

To update without losing state:

```bash
docker compose pull
docker compose up -d
```

To build the same image from this source, run `make image`.

## Native installer

The installer installs both CLIs and host dependencies, authenticates only the selected backend,
builds the wheel, preserves existing MyPlow data, and starts the stack.

Claude Code:

```bash
MYPEOPLE_BACKEND=claude ./install.sh
```

Codex:

```bash
MYPEOPLE_BACKEND=codex ./install.sh
```

Then use:

```bash
mypeople status
mypeople verify
mypeople logs
mypeople down
```

Default state is `~/.local/share/mypeople`; config is `~/.config/mypeople/queue.env`. You can change
the default Boss backend later with `mypeople up --backend claude|codex --detach`. Existing agents
always retain their original backend and session when revived.

## Python / uv

On a machine that already has Claude Code or Codex, plus tmux, ttyd, and asciinema:

```bash
uv tool install git+https://github.com/delattre1/mypeople.git
codex login
mypeople up --backend codex --detach
```

Use `claude auth login` and `--backend claude` for Claude Code.

## Mixed teams

The configured default applies to the Boss and engineers it spawns. An individual agent can use a
different authenticated backend:

```bash
mp spawn my-host/main:eng-codex --backend codex --boss my-host/main:Boss
mp spawn my-host/main:eng-claude --backend claude --boss my-host/main:Boss
```

Both backends use the same lifecycle contract: `SessionStart`, `UserPromptSubmit`, and `Stop`.
`Stop` persists the backend session ID and updates the summary. A task sent with `mp send` from one
agent routes the target's next completion notification back to that sender; otherwise the target's
configured Boss is notified. `mp revive` resumes that exact Claude or Codex session.

## Worker/client mode

```bash
UPSTREAM_QUEUE_URL=http://server-host:9900 \
UPSTREAM_QUEUE_SECRET='<server queue secret>' \
mypeople up --client
```

For cross-host terminal links, set `TTYD_PUBLIC_URL` to a browser-reachable URL for that worker,
such as `http://worker.lan:7681`. A same-host board derives the terminal host from the browser origin.

## GitHub PR watcher

Agents open PRs and ask for reviews; this plugin makes sure they hear back. Every minute it finds the
open PRs your GitHub login authored, and sends each new review, inline review comment or comment to
the agent whose board card links that PR — the Boss if no card does. Needs the `gh` CLI logged in.

```bash
export GITHUB_PRS=1                        # in ~/.config/mypeople/queue.env, then mypeople down && mypeople up
export GITHUB_PRS_AUTHOR="your-login"      # optional, default: whoever gh is logged in as
```

`python3 "$INSTALL_DIR/plugins/github-prs/github-prs.py" status` lists the PRs it watches and where
each one would be delivered. The first time it sees a PR it records the existing comments silently,
so turning it on never replays old reviews.
